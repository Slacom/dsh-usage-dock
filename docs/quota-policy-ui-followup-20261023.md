# 自动额度策略UI与阈值口径：确认要求与本地实现状态（2026-10-23）

## 来源与状态

用户明确提出设置页按渠道关注与阈值，随后要求订阅渠道按实际窗口分别设百分比阈值，**取代“5小时优先”**，并同意多窗口取最严重阶段。此后用户已明确授权一个新WorkBuddy v4.1 Flash代理负责工作区实现/构建，父只核查验证。当前已形成经本地独立复核的候选包；**这仍不是生产部署、改日常策略配置或重启的授权**。审查与试装边界见[最终交付](../.diagnostics/policy-ui-implementation-20261023/REVIEWED-DELIVERY.md)。

## 已确认要求

1. **位置**：每个渠道卡片底部提供策略区和“关注额度策略”开关。金额/积分渠道各一组双阈值；订阅渠道按实际额度窗口分别展示双阈值，不另开脱离卡片的入口。
2. **两档**：分别为预警与收尾；沿用建议性质，不变成程序强制停工或自动切模型。
3. **账户金额**：DeepSeek、MiMo等使用两个具体余额数值；单位须清楚显示并与本渠道实际币种一致。
4. **积分**：WorkBuddy等使用两个具体积分数值，不与人民币/美元金额阈值混比。
5. **订阅百分比**：每个实际可用额度窗口分别配置两项剩余百分比阈值。Codex例为5小时/周；OpenCode Go例为5小时/周/月，但不能硬造某账号未提供的窗口。
6. **不再设5小时优先级**：各窗口使用自己的阈值，互不替代。若成功采样中仅有周额度，设置页只显示周额度并只按其自身阈值判断；不是把周额度伪装为5小时的回退数据。其它订阅渠道同样按实际可识别的窗口处理。
7. **按渠道＋窗口配置**：金额/积分阈值按渠道独立；订阅阈值按“渠道＋窗口”独立。编辑Codex的周阈值不能改变其5小时阈值，更不能改变OpenCode Go周阈值。现有全局三组阈值不足以承载，不能只复制输入框而共享写入。
8. **原有范围**：不恢复已退场渠道，不重新修自定义渠道；新增控件不能抹掉其它卡片配置、凭据或现有余额告警设置。

## 实现约束（已纳入本地候选，真实GUI仍待试装）

- 设计按渠道、订阅窗口分别保存两档阈值的数据结构及旧全局字段迁移/兼容规则，避免迁移擅自开启策略或给每个窗口补同一默认值。
- 明确与现有“余额警告额度”（胶囊状态灯）字段不同：模型额度策略的预警/收尾不能悄悄复用或覆盖既有视觉告警阈值。
- 新条目不再以最短窗口代表整组策略；已实现逐窗口事实、各自阈值及触发解释。旧无覆盖配置保留legacy判定并注明，避免静默迁移。
- 已核实稳定身份rolling-5h/weekly/monthly，按精确key读写，不用数组序号/展示文案。仅覆盖当前provider已规范化的这些窗口，未来未知scope不猜测，须显式扩展。
- 区分“成功采样确认窗口不存在”和“临时获取失败”：取数失败不能被当作永久删除窗口配置。缺失窗口不冒用其它窗口阈值；窗口/采样参与判定仍遵守既有有效性和缓存规则。
- 两档顺序、剩余百分比范围、币种/积分单位、未配置/关闭语义、原始值校验及保存/放弃事务已纳入测试；不补默认阈值。暂时消失窗口保留原配置，重新出现再使用，不因失败擦除。
- 每渠道关注复选保留单一focus集合；总policy/trust位于设置页顶部且显式控制。metadata只读已有观察，未采样不造窗口，失败信封与当前配置不可读时显示失败并不借旧能力。
- 用户已确认多窗口独立判定、整体取最严重阶段，并注明触发窗口；不能求平均或设置5小时优先。
- 不把UI字段新增当作路由链已被证明；quotaTrustRouteOrder的证据与显式授权要求继续保持。

## 多窗口合并：用户已确认

用户随后明确同意：各有效窗口独立计算normal/warning/closing，渠道整体取最严重阶段（closing > warning > normal），并在提示词列出触发窗口及其当前值；不能把不同窗口的百分比求和/平均，也不按5小时优先盖掉周/月告警。

示例：Codex的5小时正常、周额度预警，则整体warning且注明周触发；任一窗口收尾则整体closing。新按渠道/窗口条目已本地实现并通过复核。为不默改旧用户：无渠道覆盖条目的旧配置保留原全局/最短窗口语义，UI注明legacy；首次编辑只迁移该渠道旧时有效窗口，不将旧阈值扩散给所有窗口。

## 渠道关注开关＋会话自动匹配：13:57用户澄清，以本节为准

**撤回协调Agent上一版的误解**：用户不是要求所有渠道默认自动参与，也不是要求删除非空quotaFocusChannels门槛。用户要求在设置页为每个渠道选择是否“关注额度策略”，会话运行时再自动按本次实际供应商路由匹配。无需每个会话手工指定渠道，不等于无需渠道授权白名单。

1. 每个渠道卡片提供“关注额度策略”开关及该渠道的预警/收尾阈值；选择哪些渠道参与，发生在设置页。
2. 渠道被勾选后，经该渠道实际调用的模型可自动使用它的额度策略；会话/父子Agent无需额外选择一个关注渠道。
3. 渠道未勾选，或实际模型供应商在插件中没有对应渠道，则不启用该渠道策略，**不注入任何quota事实或阶段规则**；不能给未关注渠道附一个“暂无额度”的占位段。
4. 主/子分别按各自本次实际provider/model路由求值，不能把父的渠道固定传给子；两者若用同一渠道则可合理使用同一可信采样。
5. 模型展示名不是计费渠道：经WorkBuddy路由调用DeepSeek模型，应使用WorkBuddy积分，而不是DeepSeek账户余额。
6. quotaFocusChannels继续作为参与白名单：空集合表示全部不参与；非空集合只允许选中的渠道。**不修改为空即自动关注全部的含义，不删除白名单检查，不自动扩大既有用户授权。**
7. 已复用focus集合承载每卡片复选框，不增第二套渠道启用布尔；新增quotaChannelThresholds只存独立阈值，用户通过UI编辑而非手写JSON。
8. 总策略、监控开关、路由信任、未知/歧义路由、独立计费池安全限制继续有效；渠道关注开关不自动开启其它闸门或补默认阈值。

当前状态：保留“每Agent路由映射＋focus白名单”，非空focus不是缺陷；每渠道关注UI、金额/积分独立阈值、订阅按渠道/窗口阈值已有本地候选并通过独立函数/组件/隔离Host检查。此前临时focus脚本不是最终交互，也不能恢复新增阈值JSON。自定义卡复用策略区，但路由仍须满足已有显式绑定/来源证明，不自动猜任意别名或计费池。

后续真实GUI父子验收仍须覆盖：父关注/子不关注、反向、双方各用自身渠道、未知渠道零注入；不要求会话再选渠道。工作区产品已改，但生产安装副本/配置未改，真实GUI验收尚未执行。
