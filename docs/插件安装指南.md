## 2. 安装 dsh-web-ui 全家桶（@linxin666/dsh-web-ui-all）

### 2.1 先配置 profile 的 pnpm-workspace.yaml（重要，安装前做）

在 `$DSH_HOME/profiles/web/pnpm-workspace.yaml`（即 `~/.dsh/profiles/web/pnpm-workspace.yaml`，Windows 与
Termux 相同）写入（源机当前内容，三处都是本机踩坑得出的经验）：

```yaml
packages:
  - .

nodeLinker: hoisted
autoInstallPeers: false
minimumReleaseAgeExclude:
  - '@linxin666/*'
allowBuilds:
  cloudflared: true
  cpu-features: true
  ssh2: true
```

- `nodeLinker: hoisted`：pnpm 严格（isolated）布局下，聚合包的 12 个依赖子包会被收进嵌套目录，`dsh web` 会报
  `Cannot find package '@linxin666/dsh-...'`；hoisted 布局可避免（旧式替代：`public-hoist-pattern: ['@linxin666/*']`）。
- `minimumReleaseAgeExclude`：pnpm 11 的 release-age 门禁可能在新版本发布后约 10 天内静默装回更旧版本
  （如 dsh-web-ui-all@0.1.5 配旧版皮肤中心，Apply 皮肤时会写独立皮肤包引用导致启动崩溃
  `ERR_MODULE_NOT_FOUND ... dsh-client-ui-skin-*`）。排除整个 scope 后安装或更新。
- `allowBuilds`：首次安装若报 `ERR_PNPM_IGNORED_BUILDS`，把这些包加入放行（pnpm 会先写入占位值，
  把 "set this to true or false" 改成 `true` 即可）。ssh2 原生 crypto 绑定编译失败会自动回退 JS，不影响功能。

### 4.1 dsh-plan-usage 补丁（3 处，均为源机必需的环境补丁）

**背景（仅 Windows 需要）**：源机 Windows ACL 沙箱用受限令牌 spawn 命令，受限令牌下 Windows schannel 无法
获取 TLS 凭据（`SEC_E_NO_CREDENTIALS`），本机所有 curl.exe 都是 schannel 后端 → 沙箱内 curl 必挂，角标显示
「获取失败 / upstream request failed」。Python 的 OpenSSL 栈在沙箱内可用，故用 Python shim 替代 curl。
**Termux 一般不需要 A/B**：Termux 沙箱已被移植版以 runnerCommand 直通方式绕过，curl 走 OpenSSL 可用；
若角标取数正常，跳过 A/B 即可。若异常且想改用 shim，先 `pkg install python`。

**补丁 A — 新增 `plans/http-fetch.py`**（目标机同一路径：`$DSH_HOME/profiles/web/node_modules/dsh-plan-usage/plans/http-fetch.py`，即 `~/.dsh/profiles/web/...`）：

```python
#!/usr/bin/env python3
# http-fetch.py — local patch for dsh-plan-usage on Windows.
#
# Why: the DSH ACL sandbox spawns commands under a WRITE_RESTRICTED token, and
# schannel (the TLS backend of every curl.exe on this machine) cannot acquire
# credentials under that token (SEC_E_NO_CREDENTIALS). Python's OpenSSL stack
# works fine there, so this shim replaces curl for the plan-usage fetches.
#
# Contract: reads a JSON spec from the PLAN_USAGE_SPEC env var, performs the
# HTTPS request, then prints the response body followed by a
# `__DSH_HTTP__<status>` marker — the same wire format curlJson in util.js
# already parses. urllib's default opener honors Windows system proxy
# settings (Clash system-proxy mode) and env proxies; direct when none set.
#
# Exit codes: 0 on any HTTP response (status may be non-2xx; the body carries
# the error), 127 on connection-level failures (mirrors curl's non-zero exit
# so util.js reports "upstream request failed").

import json
import os
import sys
import urllib.error
import urllib.request

spec = json.loads(os.environ.get('PLAN_USAGE_SPEC') or '{}')
url = spec.get('url') or ''
method = (spec.get('method') or 'GET').upper()
headers = dict(spec.get('headers') or {})
headers.setdefault('User-Agent', 'curl/8.0')  # opencode.ai 403s generic bot UAs
body = spec.get('body')
timeout = spec.get('timeout', 10)

data = body.encode('utf-8') if isinstance(body, str) else body
req = urllib.request.Request(url, data=data, method=method, headers=headers)
try:
    resp = urllib.request.urlopen(req, timeout=timeout)
    payload = resp.read()
    status = resp.status
except urllib.error.HTTPError as e:
    payload = e.read()
    status = e.code
except Exception:
    # Connection-level failure (DNS/TLS/refused): non-zero exit like curl.
    sys.exit(127)

sys.stdout.write(payload.decode('utf-8', 'replace'))
sys.stdout.write('\n__DSH_HTTP__%d' % status)
```

**补丁 B — 修改 `plans/util.js` 的 `curlJson`**（同一目录）。把原实现替换为调用 Python shim，
请求规格整体走环境变量（密钥绝不进命令行）。修改要点：

- 文件头注释增加补丁说明；新增 `import { fileURLToPath } from 'node:url'` 和
  `const SHIM_PATH = fileURLToPath(new URL('./http-fetch.py', import.meta.url))`；
- `curlJson(shell, url, opts)` 内部：构造 `reqHeaders`（Accept/Authorization/Cookie/Content-Type 逻辑不变），
  命令改为 `'python "' + SHIM_PATH + '"'`，请求规格放进 `env.PLAN_USAGE_SPEC`（JSON 字符串），
  用 `shell.resolve({ command, env, timeoutMs: 15000, stdoutMaxBytes: 16384 })` 后 `shell.run(spec)`；
  （Termux 需先 `pkg install python`，命令名就是 `python`，与 shim 内调用一致；）
- 输出解析不变：剥离行尾 `__DSH_HTTP__<status>` 标记，非 0 退出码或空体返回
  `{ err: { error: 'curl', message: 'upstream request failed' } }`，其余错误映射（api/parse/http/empty）不变。

完整 util.js 以源机文件为准（`~/.dsh/profiles/web/node_modules/dsh-plan-usage/plans/util.js`，约 6.9KB），
最稳妥的同步方式见第 5 节文件复制。

>   SSE 完整可用）+ `dsh-web-start.ps1` 等启动脚本；
> - **Termux**：在手机上跑同样的反向代理（Node 脚本，或 `socat TCP-LISTEN:3081,fork TCP:127.0.0.1:3080`），
>   并把 `trustedHosts` 里的 IP 改成 **Termux 设备自己的局域网 IP**；仅用设备本机浏览器（127.0.0.1:3080）
>   访问时无需该补丁。
> DSH 硬编码拒绝 `--host 0.0.0.0`（"would expose remote code execution to the network"），
> 局域网直连只能靠这种反向代理或插件自带的 cloudflared 公网隧道（remote-web-ui 设置里开 autoTunnel）。

| --- | --- |

## 7. 升级与易失性提醒

- dsh-plan-usage 的补丁 A/B/C 与 aionui-panel 的补丁均为**本地文件修改**，`dsh plugin` 升级/重装后会丢失；
  升级后按第 5 节方案 A 重新复制，或方案 B 重新应用。
- 升级 dsh-web-ui 前先确认 `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 仍在
  （防 pnpm 11 release-age 静默装旧版导致皮肤中心崩溃）。
- **Termux**：`npm update`/重装 DSH 会踩掉移植版全部补丁与手工编译产物（如 koffi），建议固定版本
  （`npm i -g @deepseek-ai/dsh@0.1.0-rc.6 --ignore-scripts`）；本指南的插件补丁在重装插件后同样需重新应用。
- 源机曾遇卡巴斯基 PDM 误杀 DSH 沙箱组件（`@deepseek-ai/dsh-sandbox-windows-acl\lib\runner.js`）与 node.exe：
  若目标机杀软拦截，把 npm 全局目录加入排除项，必要时把 node.exe 加入受信任应用程序（勾选"不监控应用程序活动"）。（Termux 无此问题）
