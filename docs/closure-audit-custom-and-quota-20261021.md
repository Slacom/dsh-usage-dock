## 1. 先答两个问题

**为什么拖了这么久？** 既有合理的需求调整，也有原缺陷未修全，且多次能确证是**修补引入新回归**。不是都能归因于第三方、网络或用户不断改需求。此前审核也偏逐个反例推进，没有尽早把所有公开错误出口和GUI/工具/缓存交错放在同一矩阵里；这是覆盖方式的不足。

**额度策略构建成功了吗？** 核心代码已进入本地包并有本地测试，不能说“没做”；但完整自动策略尚未验收，不能说“全部构建成功、可安全开启”。动态context与规则受共享来源状态影响，仍被R8的P1误收尾阻断；策略UI和真实宿主注入/重试等还需独立交付/验收。

## 3. 最终归并为三个根因块，不是继续零散补丁

### A / P1：采样操作与票据归属没统一

[第八轮反例](recheck-v0.9.1-round8-20261021.md#L17-L49)：B=9000工具缓存预热→GUI A=1挂起→当前工具identify确认B并命中缓存、零新HTTP→旧A迟到却进入context/closing。

最新票据不等于本次操作的票据。全局latestTicketOf升级了旧A的权限，不能用“只提升一张”证明旧票安全。

**一次改到根：**定义唯一采集操作标识，冻结来源/实际发送凭据、入场序号、激活代次与本次票据归属。identify/缓存命中没有取数票时不得修改其它操作的票。旧凭据解析迟到也不得重新激活旧源。不能靠取消所有缓存、重复查询余额、完成时重签新序号或放宽epoch掩盖。

### B / P2：取消信号没有贯穿网关传输

[第八轮取消证据](../.diagnostics/review-custom-provider-round8-20261021/gateway-probes.log#L13)：signal已abort但remaining仍5000，网关仍发status及packages。预算归零已修，不等于取消已修。

**一次改到根：**入口/凭据返回/每次新I/O检查父取消，连接/正文组合父signal与超时；取消不计T、不影响其它活消费者。保留已通过的0/负预算零I/O、私有任务实际剩余、2.5秒明细保底。

### C / P2：公开异常DTO没有统一，仍把err.message当安全文本

R7/R8修好了malformed JSON的主wire、账号列表及注册路由，但[网关catch](../plans/workbuddy.js#L873-L878)与[账号列表catch](../plans/workbuddy.js#L746-L748)仍直接拼异常message。

这次不仅是人为抛含哨兵的异常，还用**Node原生fetch/Headers**：凭据服务返回带换行的合成已存Key，Headers合法性检查自然抛错并带出输入；两类公开输出均回显合成Key前缀。用data:响应替代真实网络，未接触任何用户Key。通用自定义请求层对同类错误固定分类，未出现此回显。

另以**真实注册GUI与账号路由**确认回显能到公开JSON：[路由探针](../.diagnostics/closure-audit-20261021/public-errors.mjs)、[结果](../.diagnostics/closure-audit-20261021/public-errors.log)。它是异常/非法Key配置才触发，不代表正常Key已泄漏；但secret不回显边界不能因配置错误失效。

**一次改到根：**统一所有公开失败DTO，固定分类/HTTP状态/安全诊断码；不要直接拼原始exception/parser/body。可额外拒绝非法头字符，但不能把“删换行”当作全部错误出口已脱敏。模型工具白名单继续保持，不反过来开放原文调试。

## 5. 额度策略实际完成度

核心构建与完整产品验收必须分开，不借机给自定义渠道增加策略UI/真实计费池/Android等新的收口条件。

| 层次 | 当前状态 | 能否称完成 |
| --- | --- | --- |
| 本地包与基础取数 | 1824项既有本地回归、包/源码一致；用户已有正常加载/积分显示证据 | 基础构建成立，不等于自动策略已真机验收 |
| 配置与三种阈值 | [配置schema](../plans/usage-policy.js#L29-L68)有百分比/金额/积分两档、币种、关注白名单和精确路由绑定 | 已实现 |
| 共享观察与三阶段 | 观察器、来源/身份、失败分类、T宽限/5次、normal/warning/closing及白名单投影 | 核心已实现/本地测试；来源并发仍受阻断A影响 |
| 动态规则投放 | [注册动态context](../index.js#L800-L804)，不再靠常驻section；本地可重求值规则 | 已实现，不等于真实请求/同step重试已验证 |
| 额度更新机制 | 复用GUI/主动工具采样，context只同步读状态，不额外查询供应商 | 已实现；不是无GUI也保证更新的独立Host定时监控器，也不是每次模型请求都重新查余额 |
| 策略设置UI | 当前客户端没有quotaPolicyEnabled/阈值/关注/绑定对应交互控件，构建记录亦明示未做 | 未实现；只能改配置字段，不是可直接点开的完整策略产品 |
| 真实宿主注入/同step重试 | 尚无本次实际组装提示词中插件context段和重试撤旧规则的安全取证 | 未验收，不应报成功 |
| 真实账号/额度池与窗口 | 有保守路由绑定/来源及池闸门，但没有证明所有网关每次派发的具体计费账号；当前窗口规则仍需业务确认 | 功能有限/待确认，不能把模型名当资金来源 |

**默认不会自动启用。** 当前代码的quotaPolicyEnabled与quotaTrustRouteOrder都默认false，关注列表空、阈值0、币种空。[默认值依据](../plans/usage-policy.js#L31-L68)。因此“安装了包但没有出现收尾提示”不一定是故障；也不建议在阻断A未修时为了测试而直接强开信任闸门。

本轮另核7组策略相关测试，**269项全部通过、0跳过**，是1824项既有套件的子集，不与1824重复相加。[独立完成度表及逐组日志](../.diagnostics/closure-audit-20261021/policy-status.md#L28-L43)。N12等测试是在合成服务中反复求值同一个context闭包，不是实际执行Host.refreshContext或最终LLM重试请求；不能偷换成真机闭环。

这是**提示词层面的分阶段建议/约束**，不是阻止后续模型请求的硬限流器。工具返回过余额、GUI显示正常，都不能单独证明动态规则真的进入了本次模型提示词。总开关关闭不自动注入；启用且路由/关注条件成立但无有效阈值时仍可输出normal事实，不擅自补阈值。

策略应另设有限交付节点：先修共享来源一致性；由用户选择“配置式、无专用UI的受限核心交付”或另外完成策略UI，再在获授权的真实Host中只取插件context安全片段，验新请求/工具续轮/同step重试的normal、warning、closing、失败与撤销。不要为验收读取整份用户提示词或真实Key，也不要为制造低余额而真实消费账号。实际计费池和是否同时保护周限须明确支持范围，不冒充都已验证；这些不并入自定义渠道本轮修补。

## 6. 最终有限验收清单与停修条件

范围冻结：不再改外观、不加新供应商/自定义格式/窗口策略，不恢复国际渠道，不借审核开发安装更新能力。

执行方下一份包应一次提交A/B/C根因修复及统一行为回归，不再只修一条报错：

1. 冷启动、同Key、已知A→B第一新值都正确发布；旧A/旧凭据迟到不回填。
2. B缓存预热＋挂起A＋identify回B命中缓存，释放旧A后不得出现1/closing；无缓存新B提交正控制也通过。
3. 不靠禁用成功缓存过关；缓存命中不伪造新采样时间，401后真实重试、P/A封存不被T/缓存冲掉。
4. 0/负/短预算、排队/凭据迟到/正文超时，不能在截止后新增HTTP；私有任务不重获整份8秒。
5. 父signal在入口已取消/凭据等待中取消/正文中取消都生效；共享任务仍有活消费者时只撤离取消者。
6. 所有公开错误出口同时覆盖malformed、transport throw、原生非法Header，GUI/账号路由/工具均不含合成Key/body片段；合法错误分类仍可操作。
7. 已有按id保存/删除/混排、草稿放弃、secret路径精准mutate、配置证明与旧响应过滤继续通过。
8. 0/负数/缺值、单位/币种、大小限制、同origin/redirect/TLS、点名只取启用渠道、停用删除均保持；不重写已通过UI。
9. WorkBuddy正常合计、短明细保底、404账号汇总及能力记忆保持；不把未提供的明细当故障，不降低余额轮询频率。
10. 同一最终哈希下正确期望测试全部通过、包/源码一致；再做一次用户正常启动、卡片与工具值对应的最小实机验收。

旧诊断里“assert缺陷存在而exit0”的脚本不能直接当验收绿灯；应转换为**期望正确行为**，修前红、修后绿。按源身份/操作归属/绝对deadline/公开错误DTO这几条不变量统一实现，避免每个入口各维护一套约定。

**结束条件：**A/B/C及上述既有能力回归在最终包同版本通过，自定义渠道主线即可冻结；不把后续策略UI、业务窗口与真实池证明继续绑在这条主线上。出现新的错账/泄密/卡死证据仍应处理，但不再以未排期功能或低优先视觉意见无限延长收口。
