### A. `ctx.get('connection')` 是 `HostConnectionService`，公开面含 handler factory 与 `fetch(request, peer)`，但**均需 owner principal Peer**（见 rev4 更正）
`dsh-client-connection/lib/index.js` 导出：`{ API_PATH, CONNECT_PATH, Config, HostConnectionService, Peer, RpcId, apply,
clientRequestSchema, inject, name, rpcErrorSchema, rpcIdSchema, rpcMessageSchema, rpcResultSchema, serverResponseSchema, transportError }`。

- 服务以 `super(ctx, "connection")` 注册 ⇒ `ctx.get('connection')` 即该服务实例。
- **`connection.fetch` 只暴露 `register`**：
  `get fetch() { const owner = this.ctx; return { register: (route) => this.registerFetchRoute(owner, route) } }`
  ⇒ 这是你读到的 `connection.fetch.register({ path, methods, requestBody, fetch })` 的注册侧；**公开对象上没有 `.dispatch()`**。
- `connection.handle(channel, handler)` / `connection.intercept(channel, matches, handler)`：同样只是**注册**。
- 真正的请求受理是 **带 peer 参数**的：`async fetch(request, peer)`（`lib/index.js:891`），且入口先过
  `admit(request)` = `isTrusted(request)`（Host/Origin fence、`trustedHosts`/loopback/bind 授权）→ 失败 `403`；
  然后必须是 **已认证的活动 Peer**（`browserAuth.isAuthenticated` / `authenticateApi`），否则 `401`。
  ⇒ **不存在**「Host 直接构造 `Request` 走 `/api` 且免鉴权 = trusted in-process」的公开入口；
  `fetch(request, peer)` 需要**合法 peer**，不是可自行伪造的信任上下文。

### B. Host 侧唯一公开的"可信进程内"通道：`createPeer()`
- `createPeer(options)` 是公开方法：`return new Peer(this.ctx, options)`（注释：*Create one in-process Peer owned by the Context that read this service*）。
- ⇒ Host 若要与插件**自有** channel 交互，合法路径是 `createPeer()` 拿 Peer 再按 channel 契约走，
  **不是**伪造浏览器请求、**不是** localhost 自发 HTTP、**不是**去碰 private 路由表/handler。

### C. `loader.entries()` 能判"实际 active"（`cordis-plugin-loader`）
- `*entries()` 迭代 tree 条目（含嵌套 subtree），条目暴露 `fiber`、`_initTask`、`fiber.inertia` 等运行时状态；
  另有 `entry.fiber?.dispose()` 等。
- ⇒ **可以用公开 API 判定某插件是否真正实例化/active**，**不必**依赖 `import()` 成功，也**不必**读该插件的状态文件。

## 8) 据此的边界（最终）
1. **不允许**假设或使用「Host 可信 `/api` RPC / FetchRouter.dispatch」。公开面只有 `register` + 需 peer 的 `fetch(request, peer)`，
   且强制 `isTrusted` + 已认证 Peer。**不伪造 owner session、不走 localhost HTTP、不绕 trusted 检查。**
2. Host 需要跨插件数据时，只用 **`createPeer()` 得到的合法 Peer + 该插件公开 channel 契约**；若对方只注册了 `/api` fetch 路由，
   则 **Host 侧没有可信直调**，此时只能落 **Browser-only** 方案（仅选中来源、仅侧栏展示，不伪造 Host `usage_status`、不喂提示链）。
3. 「未启用」判定：用 `ctx.loader.entries()` 的公开状态（fiber/inertia），**不**用 `import()` 成功、**不**读未选中来源的状态/usage 文件。
