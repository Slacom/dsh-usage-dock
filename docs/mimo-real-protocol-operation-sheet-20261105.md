## 1. 验证阶梯（每一级单独许可，不自动递进）

| 级 | 内容 | 前置 | 允许触碰 |
| --- | --- | --- | --- |
| **V0** | 未来离线诊断器（同进程、假 transport、无网） | **亦需一次代码许可**（新增代码本身也受"未许可不改代码"约束） | 只能跑合成、0 网络 |
| **V1** | 一次**真实登录的结构观察** | **另许** + 明确告警：**可能触票** | 只记录非敏感结构 |
| **V2** | **用户事前预期标识** 与 **实际可信身份的 namespace/映射证据** | V1 通过 + 另许 | 只取身份，不取余额 |

**V2 的口径（容易写错，必须分开）**：
- **expected = 用户事前表达的预期**（本人写/选的标识）。它是**用户意图**，**不需要**另开一个官方登录来"证明"；
- **actual = 实际可信身份**，其真实性**来自受信认证**（真实验签/受信通道），不来自用户的说法；
- **禁止由 actual 反算 expected**（那样等于自证），也禁止用 mask 相似、本人自述替代；
- **scope / method / path 仍为未知时只写 `TBD`**，不得用推测值填表，也不得因此新增任何实操。
| **V3** | 逐 hop 的票交换 / 账户 / 余额 | V2 通过 + 另许（逐 hop） | 每 hop 单独授权 |

**铁律**：V1 **不是**"只看结构就安全"——一次登录结构探查本身就可能已触票。
身份失败（`expected≠actual`、身份不明、命名空间不可比）**不得**进入余额段。

## 2. 每个 hop 必须写明（缺一不得执行）

1. **exactOrigin** + **exactMethod**（例：`https://…` + `GET`；**不允许**"大概 GET"、不允许编造厂商 URL）
2. **exactPath**（含是否带 query）。**含敏感值的 query 一律不得写入任何配置/文件/文档**，
   只允许**内存内短暂持有**并在本次操作结束后立即丢弃；文档/聊天里只出现脱敏模板
3. **purpose**（如 `loginStructure` / `identityMap` / `balance`，与授权一一对应）
4. **sourceProof**（origin / initPath / sid / callback / redirected，逐字段精确匹配）
5. **maxHops = 1**（默认**不跟跳**；未知候选目标**不自动跟随** redirect）
6. **认证材料种类**（只写**种类**：cookie / query 票 / header 票…；**永不写值**）
7. **操作者**：必须是**本人本机**本人操作；不得代持、不得转交第三方
8. **次数**：默认 **1 次**；任何重试必须显式写明"无自动重试"或明确上限
9. **超时**：每 hop 一个**待批准的保守值**（未批准前不执行）
10. **停止即清内存**：取消/超时后必须证明凭据、grant、数值、mask、账号关联全部释放
11. **路径/方法未知时只写 `TBD`**：不得用推测值填表，也不得从其它产品推断

任何一项缺失 ⇒ 该 hop 不执行。域级 allowlist **太宽**，不接受。

## 3. 目标签名与私密性

- 目标签名（exactOrigin/exactMethod/exactPath/purpose/maxHops）中**含敏感 query 的部分**
  **不得写入任何配置/文件/文档/提交**，只允许在本机内存内短暂持有并在本次操作结束后立即丢弃；
  评审与聊天里只出现**脱敏模板**（占位符 + 结构/长度），不出现真实值。
- **禁止**把以下内容发进聊天/文档/提交：原始 URL、query、cookie、`serviceToken`、`passToken`、
  原始账号/手机号/邮箱、`Set-Cookie` 原值、HAR、抓包文件、截图中的票。

## 4. 真实验证时的报告纪律

- 只回报**非敏感结构**：字段名、类型、长度区间、状态码、错误码类别、hop 顺序、次数、耗时区间。
- 单次成功与**至少一轮持续刷新**必须**分开**验并分开报告（一次成功不证明可持续）。
- 失败必须区分：`auth rejected`（401/403）/ `transient`（网络、超时、5xx）/ `parse` / `identity`。
  **401/403 只能写"授权被拒/失效"，不得写"厂商侧过期"**（TTL 未证）。

## 5. 取消 / 超时的清理证明（必须给，不给不算通过）

1. 取消后**新增目标请求数 = 0**（可用计数/端点记录证明）；
2. 超时后**无自动重试**；迟到响应的结果**不写入**任何状态；
3. 本地清空清单：凭据、grant、数值、mask、账号关联**全部**释放；
4. 若声称"上游已注销"，必须另有上游侧证据；仅有本地 abort 时只能写"本地已停止"。

## 6. 与本地实现的关系

- 本地 `plans/mimo-auth/session-display.js` 的 DI adapter 形状就是 V3 的**接口位**：
  `adapter({credential, purpose:'balance', signal, deadlineAt})`。真实实现只能替换 DI，
  **不得**让路由接受 URL / credential / purpose 之类越权字段（当前实现已 400 拒绝）。
- 合成 DI 已把边界固定：身份不明/变号 ⇒ 停；缺币种 ⇒ 判 parse 失败；401/403 ⇒ 停并清值；
  14 次尝试上限、15 min 本地界、无自动重试。**注意：这些是临时本地保守界，随产品批准调整**，
  不是真实适配的正式政策，也不得据此声称"厂商侧就是 15 分钟有效"。
- `min(已证 exp, 本地界)`：只有受信适配能证明厂商 exp 时才取 min；未知时只写本地界，
  **不主张等于厂商有效期**。

## 7. 触发条件（缺一不做）

1. 用户对**该级**验证单独、明确授权（V1/V2/V3 各自独立）；
2. 目标是本人账号，且是**本人本机**操作；
3. 已写明本 hop 的 §2 八项；
4. 已知悉"**可能触票**（一次登录结构探查就可能已触票）、可能触发上游风控/审计"；
   **只读余额查询不应被描述成"必然产生会计影响"**——是否计费/记账未证。
5. 报告按 §4 纪律，清理按 §5 证明。
