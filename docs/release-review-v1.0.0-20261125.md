## R1 · P1 · MiMo 自动取 Key 未绑定主机

**症状。** 插件 Key、固定候选名均缺失，且未冻结凭据时，`providerKeyOf` 仅按 provider id 或 `displayName` 中的 `mimo`／`xiaomi` 识别来源，再用 `apiKeyEnv` 取 Key。
它没有校验 `baseURL` 的 origin，余额调用则固定以 `api-key` 头访问 Xiaomi API。
[自动选取](../plans/mimo.js#L44) · [名称匹配与解析](../plans/mimo.js#L58) · [固定请求](../plans/mimo.js#L128) · [取数入口](../plans/mimo.js#L192)

**已做模拟。** 同一第三方 `baseURL` 和合成 Key，provider id 为 `mimo-relay` 时 `hasMimoApiKey` 返回 `true`，改成 `relay-gw` 后为 `false`。模拟确认错误凭据被选中，调用去向由源码确认。

**修复目标。** 自动复用前校验规范化 origin，只接受明确可信的 Xiaomi API 来源。缺失、无效或第三方地址跳过，统一取数和 Key 存在性判断的规则。保留插件显式 Key 和明确约定的固定凭据入口。

**最小验收。** 合成第三方目标即使名称命中也不解析或使用其 Key，且不发起余额调用。
可信 Xiaomi 目标仍可自动选中，显式 Key 仍按优先级生效。只用 mock 观察凭据解析和请求参数。

## R2 · P1 · 同一 Host 外部切换账户后，网页灰显旧账户额度

**症状。** 网页已显示账户 A。DSH Go 或同一 Host 的另一窗口切到 B，B 暂时取数失败时，网页可能按本地身份和失败计数把 A 的额度灰显出来。
原生切换会清理 Host 观察，但额度响应缺少供网页判定同一账户身份的代次。
[额度响应](../index.js#L2106) · [原生切换](../index.js#L2679) · [网页身份](../client.js#L272) · [旧值回退](../client.js#L2865)

**修复目标。** Host 为 Codex 提供与本批采集身份匹配的脱敏代次，成功与暂时失败都要可判定。
客户端得知账户切换后立即作废旧身份的显示、回退缓存与迟到响应。
先前请求的结果不能被标成新代次，也不能覆盖已经应用的新代次。代次不携带账号标识、凭据或可逆身份数据。

**最小验收。** 用合成 A/B 在同一 mock Host 跑一条序列。

1. 网页取得 A 的成功额度。经原生或独立 Host 入口切 B，使 B 首次取数暂时失败，网页只显示 B 的失败或等待状态。
2. 让切换前的 A 请求迟到，确认其额度不会回填。B 后续成功后，可在 B 自己的短期失败时继续灰显 B 的额度。

## R3 · P2 · 旧 Codex Subscription 适配 POST 仍可写第三方插件

**症状。** 网页与原生设置已撤掉「一键适配」，运行时仍注册 `POST /api/plan-usage/codex-subscription/apply-patch`。
该入口可调用写入帮助函数，目标是第三方插件目录。Host 还传入已无人消费的原生适配状态和执行回调。
[POST 注册](../index.js#L2231) · [原生回调接线](../index.js#L452) · [原生端说明](../plans/dsh-go-native.js#L1628)

**修复目标。** 撤掉插件运行时写入口及无人消费的原生回调，顺带清理随之失去引用的帮助代码。按实际引用保留维护工具仍需的补丁模块和清单。[维护工具的引用](../tools/patch-codex-subscription.mjs#L30)

**最小验收。** 用 mock 注册器确认旧 POST 不再注册，原生依赖不再暴露两个回调。静态核对维护工具仍可解析其依赖，任何验证均无需执行补丁写入。

## R4 · P2 · 网页切换收到 HTTP 200、`ok:false` 时静默

**症状。** Host 用 HTTP 200 和 `ok:false` 表达选择失败。网页把响应当完成，继续刷新权威状态，却没有反馈这次切换失败。
用户看到原账户仍被选中，无法判断发生了什么。
[网页切换](../client.js#L1181) · [Host 失败分支](../index.js#L2589)

**修复目标。** 网页检查业务结果，业务失败时显示现有安全错误文案或相应本地化兜底，保留 Host 的 active 状态，并恢复可交互。刷新权威状态时保留本次错误提示，过期操作的回包不得覆盖新操作状态。

**最小验收。** mock 返回 `200 {ok:false}`，确认 A 仍有效、可见失败提示并可重试。对照 `200 {ok:true}`，确认刷新后正确显示 B。

## R5 · P2 · 移除最后账户在确认与删除间有竞态

**症状。** 移除 A 发现它是最后一个账户时，事务外再读确认，随后无条件删除整条插件私有记录。
如果 B 在确认后、删除前新增成功，B 可能一并消失。删除后的重读无法恢复 B。
[确认窗口](../plans/codex-account.js#L1458) · [整条删除](../plans/codex-account.js#L1489)

**修复目标。** 删除 A 与新增 B 交错时保住已成功保存的 B，避免调用链对同一把锁重入。
查清宿主凭据 API 的保证后选择兼容方案，例如带版本条件的原子删除，或宿主事务支持且读写兼容的空态。
能力不足时可安全重试或明确返回冲突。

**最小验收。** 用 mock 让新增 B 在最后账户移除尚未提交时交错，断言 B 未丢、操作不挂起、返回结果与持久状态一致。
对照无并发时移除最后一项，确认读取和 UI 都得到空态。
