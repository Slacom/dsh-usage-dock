## 3. P0：先保证口径可信

采用路线图方案 A：保留已用计算，面板脚注及胶囊 tooltip 明确“已用”；Codex 明确“剩余”。GLM / OpenCode 同批核对，避免只解释 Kimi。

解析按窗口 fallback，不整块替换：

1. 优先有效的旧版 `usage` / `limits[]`；缺失或不可解析时才尝试相应新窗口。
2. `usages.limit_5h` 补 5 小时；月度优先 `limit_month_total`，缺失时再考虑 `limit_month_code`。
3. `used_ratio` 的范围、`reset_time` 的时间类型先以脱敏 fixture 核对，不能从字段名猜单位；不要把 ratio-pool 月限误映射成周限。
4. Cookie 月度增强与 ratio-pool 月限的覆盖优先级须在实现前固定并测试。
5. 覆盖 0 / 1 边界、非法数值、空对象、缺窗口、两个响应格式并存与可选 Cookie 失败；不能把缺数据转换成 0% 已用或 100% 剩余。

## 4. P1：工具契约先行

建议提取共享“当前配置 + 渠道取数”编排，使 Web 和工具复用业务逻辑；Web 继续即时取数，不因工具缓存变慢。

工具契约需要在实现前固定：

- 每渠道多个 `windows`，保留 rolling / weekly / monthly / primary / secondary 等窗口身份；不能只压成一个百分比。
- `kind` 区分 balance / quota / credits；数值必须带币种或积分单位。上游只给比例时，`remaining` / `limit` 为空，不反推虚构额度。
- 明确 `percentMode`；可另给统一的剩余比例，但同时保留来源口径。
- `state` 不只 ok / low / exhausted，还要表达 unknown / error / disabled；凭据缺失、登录过期、未安装和传输失败不能冒充耗尽。
- `fetchedAt` 是成功取数时间，不是每次调用时间；TTL 内复用不等于 stale；过期/失败不能无标识返回旧成功结果。
- `low` 基于用户配置；没有模型策略阈值就只报数，不能偷偷套用示例 20%。现有余额告警与影响 Agent 行为的授权应分开说明。
- 不把默认所有渠道的最低余额当成当前模型额度；须允许明确选定策略关注渠道，无法映射时不猜。
- 仅返回白名单数字、状态与时间；不要透传可能含敏感信息的上游 message、原始响应、套餐名称或配置。

工具侧使用 30 秒短 TTL + single-flight；按配置/凭据版本隔离（不在日志或返回值暴露凭据），停用或修改配置即失效。成功与错误缓存策略分开规定，不新增隐式 stale-if-error。

通过 `ctx.get('tools')` / `ctx.get('systemPrompt')` 获取可选服务，处理 undefined / null / throw；不 import 宿主工具包，不加入硬 inject。正式注册前需核对实际宿主的定义、输出 schema/render、调用与卸载契约，用 mock 做测试不等于宿主验证。

## 5. P2：默认关闭的策略

- `quotaPolicyEnabled` 默认 false；阈值、关注渠道与单位在设置页显式配置，并 `.volatile()`。
- 未配置阈值、数据未知/过期/错误、无法确认当前渠道时，只解释现状，不强制劝停。
- 建议行为：完成当前最小工作单元 → 检查变更 → 跑必要测试 → 保存进度与后续操作 → 收尾。提示词只能建议模型行为，不能保证每一步调用工具或硬性停机。
- 提示调用频率以一次任务 1–2 次为宜；注册与配置切换后不得残留重复工具或过期策略段。
