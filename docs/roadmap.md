## 方向 1：详情面板内提供 DeepSeek 充值入口

**提出**：2026-10-10（用户充值实测后提出）

**需求**：在胶囊展开的详情面板里，为 DeepSeek 余额行提供一个「充值」按钮，
与 DSH「设置 → 账号与余额」里的充值入口**一致**；点击后**跳转到 DSH 内的充值界面**
（即设置里那个「充值」按钮打开的页面）完成支付。

**动机 / 实测场景**：余额低于阈值时胶囊红灯提示「请及时充值」，但用户得自己想到
去「设置 → 账号 → 充值」，链路绕。详情面板里就地给入口，告警 → 充值一步到位。

**参考（DSH 内嵌充值页的实际形态，2026-10-10 截图）**：

- 顶部「‹ 返回 DeepSeek Harness」，说明是 DSH 内嵌页面/路由，不是外部浏览器；
- 「在线充值 / 对公汇款」两个 tab；金额档位 ¥10 / ¥20 / ¥50 / ¥100 / ¥300 / ¥500 / 自定义 / 查看价格；
- 支付宝 / 微信支付，「去支付」；「金额将充入当前帐户（180\*\*\*\*\*\*\*23）」。

**实现要点**：

1. **先研究「设置 → 账号与余额 → 充值」按钮的跳转机制**（内部路由 or 服务调用），
   让详情面板的按钮复用同一条入口，不要自己拼 URL；
2. 按钮放在详情面板 DeepSeek 余额行附近（client.js 的详情面板渲染处）；
3. **只在账号登录时显示**（取数 `via === "account"`，即走 `deepseekAccount` 服务）；
   API Key 回退模式下不显示——那是 API 余额，没有账号充值语义；
4. 与方向 2 联动：充值完成回来后余额要立即刷新，否则按钮充值完面板还是旧数字。

**涉及文件**：`client.js`（按钮 + 跳转）、可能需要研究 DSH core 的充值页路由约定。

## 方向 2：充值后胶囊余额与设置页余额实时同步

**提出**：2026-10-10（用户充值实测后提出）

**需求**：在 DSH 官方账号充值完成后，**设置页「账号与余额」里显示的余额立即更新，
胶囊里的 DeepSeek 余额却还是充值前的旧值**——两者应当同步。同样只在账号登录时实现。

**动机 / 实测场景（2026-10-10 截图）**：

| 时刻 | 设置页「充值余额」 | 胶囊「DeepSeek 余额」 |
| --- | --- | --- |
| 充值前 | ¥4.42 | ¥4.42（红灯，「余额低于 10 元，请及时充值」） |
| 充值 ¥30 后 | **¥34.42**（立即更新） | **¥4.42**（旧值，未变） |

设置页的数据链路显然比胶囊的 30 秒轮询「新鲜」，两条链路不一致，观感上就是
「设置里明明有钱了，胶囊还在喊没钱」。

**现状数据流**（排查结论，实现时从这里出发）：

- 胶囊：client.js 每 **30 秒** `fetch('/api/plan-usage')` 轮询一次
  （`setInterval(load, 30000)`）；Host 端 `/api/plan-usage` **无缓存**，每次请求现取；
- DeepSeek 账号余额：Host 经 `ctx.get("deepseekAccount").getBalance(...)` 读取
  （`plans/deepseek.js`），返回投影结构（见 AGENTS.md 第 5 节坑 #6）；
- 所以「旧值」主要卡在**客户端轮询间隔**，以及 `deepseekAccount` 服务内部
  是否有自己的缓存/更新事件——这点要先摸清。

**实现要点（按优先级）**：

1. **摸清设置页余额的数据源**：DSH「账号与余额」页读的是哪条链路（Remote 订阅？事件？）
   ——能复用/订阅同一来源最好，这本身就是「与设置一致」的保证；
2. **事件驱动刷新**：充值流程结束、或账号余额变更事件触发时立即刷新胶囊；
   若 `deepseekAccount` 有 subscribe/事件机制就订阅它；
3. 保底方案：在**可感知的时机**主动 `load()` 一次，不等 30 秒轮询——
   窗口 focus / `visibilitychange` / DSH 路由返回（充值页「返回 DeepSeek Harness」）
   / 详情面板展开时；
4. 可调低轮询间隔（如 30s → 10s）但**不作为主方案**：既费请求又解决不了
   「秒级同步」的观感问题；
5. **只在 `via === "account"` 时启用**这些即时刷新路径；API Key 模式维持现状。

**涉及文件**：`client.js`（刷新时机）、`plans/deepseek.js` / `index.js`（数据链路）、
可能要研究 DSH core 账号余额的订阅/缓存机制。
