## 更新摘要（GitHub Release 正文）

- 自定义余额渠道改为「选择已配置的模型来源 + 填写该来源下的余额接口路径」，不再需要手填 URL 与
  Key；可添加多条、启停、删除与排序，并与内置渠道在同一个列表里按你的顺序混排。
- WorkBuddy 改读「设置 → 模型」里的 WorkBuddy2API 网关积分，可按账号筛选合计范围；
  国际版 `workbuddy-ai` 退场（旧配置与共享凭据保留，不再取数、不再显示）。
- 新增只读工具 `usage_status`：模型可以主动查询已启用渠道的余额/积分/窗口剩余，输出脱敏、
  不含凭据与上游原文；不继承「关注额度策略」名单。
- 新增可选的「额度策略」：一个总开关 + 每个渠道的「关注」与两档阈值（预警/收尾）。
  订阅渠道按实际窗口分别判定、渠道整体取最严重阶段；主会话与子 Agent 各按自己本次**已观察到的路由**匹配，
  未关注/未知/歧义路由不注入任何内容。关闭总开关时渠道策略区整块隐藏，已保存的关注与阈值保留。
- 设置页重排为单列卡片：顶部一行显示总开关与状态，长说明与「连接与凭据」默认折叠；
  底部保存/放弃吸底并提示「有未保存更改」。
- 稳定性：配置/凭据身份变化时旧值与在途请求立即作废；保存先校验、一次提交、只写变更字段；
  失败保留旧值而不是清空（短暂网络失败灰化保留，鉴权/配置错误立即提示）；只读查询与自动提示互不影响。
- 退场的 Kimi Code、GLM 智谱、GLM Z.AI 与 `workbuddy-ai` 不再显示、不再后台取数；
  旧配置字段与已有模型凭据**原样保留**，不做清理。

## 一、渠道变化

**退场 id**：`kimi-code`、`glm-zhipu`、`glm-zai`（0.9.0）与 `workbuddy-ai`（0.9.1 内部整改并入本版）。

- 胶囊、详情面板、设置页、排序候选里都不再出现，也不再后台取数（注册表是唯一取数来源）。
- 旧配置字段与共享模型凭据留在 profile 里，作为普通未知键保留：不删除、不清空。
- 国内 WorkBuddy 不再是「WorkBuddy Connect 登录」路线：改读模型配置中的 WorkBuddy2API 网关
  （`<origin>/status`，复用该来源 Bearer Key），并可只合计部分账号。

## 二、自定义余额渠道

- 每条 = **模型来源 + 余额接口路径 + JSON 键路径**（可选币种、可选扣减键）。
  主机与凭据从所选来源派生，用户不再手填 URL/Key，也不需要单独确认目标主机。
- 只支持 `GET` + `Authorization: Bearer` + JSON；**不跟随重定向**，TLS 证书校验始终开启；
  响应体上限 256 KiB、单条 10 s / 整批 20 s、并发 3、最多 12 条。
- 安全边界（按实现如实说明）：来源模式把「用户自己在『设置 → 模型』里配置、且正在使用的服务商」
  当作**信任边界**，因此**不做**私网地址拦截、**不做** DNS 钉 IP（fake-ip 代理不会再被误判为内网）；
  代价是失去"检查的 IP 就是连接的 IP"这层保证，连错服务器会因证书校验失败而握不上手。
  仅**旧的独立 URL 兼容路径**仍按公网地址检查 + 连接期 IP 绑定处理。
- 凭据：来源模式下凭据取自该 provider 的 `apiKeyEnv`，**只用于本次请求**、不写入配置；
  不要求也不新建 `customKeys`。`customKeys`/secret 路径仅用于**旧条目兼容与清理**，设置页永不回显。
- 每条带身份（公开元数据 + 凭据指纹 + 公开修订号）：改来源/路径/币种/凭据后旧值与在途请求立即作废。
- 失败分层：暂时失败灰化保留旧值，**持续失败后**才报告错误（判定以 Host 给出的统一状态为准）；
  鉴权/配置错误立即提示。
- 「累计额度」不被当成「余额」：需要时用扣减键表达「累计额度 − 累计用量」。

## 三、额度自动感知（只读查询 + 可选策略）

**只读工具 `usage_status`**（模型主动调用）：

- 查询范围：**给 `ids`** 时 = 点名 ∩ 已启用 ∩ 受支持；**省略或传空数组**则查询全部已启用且受支持的渠道。
  停用/退场渠道不取数、不发凭据。
- 输出为白名单重建的脱敏投影（状态、余额/积分与币种、窗口剩余、采样时间），
  不含 URL、账号、Key/Cookie、上游原文与内部指纹。
- 30 秒成功缓存 + single-flight + 按配置摘要分代；单次 8 秒预算，超时标 `missing` 不报错。
- 缺 `tools` 服务时静默跳过，不影响胶囊与设置页。

**可选「额度策略」**（给模型的一段建议，默认关闭）：

- 页面顶部只有**一个**总开关；打开时成对写入两个历史授权字段，关闭时成对关闭。
  旧配置只打开一半会显示「旧版设置未完整启用」，插件不会自动补写。
- 每个渠道卡片底部有「关注额度策略」与两档阈值：金额型按该渠道实际币种、积分型按积分、
  订阅型按**实际采样到的窗口**分别配置；0 = 未配置，不补默认值。
- 各窗口独立判定、渠道整体取最严重（收尾 > 预警），提示会说明是哪个窗口、当前多少触发。
- 总开关关闭或只开一半时，渠道策略区整块隐藏；已保存的关注与阈值保留，重新开启原样恢复。
- 主会话与子 Agent 各自按本次**已观察到的路由**匹配，不继承对方的选择；未关注/未知/歧义路由零注入。
- 明确边界：合并不代表对第三方连接插件改写顺序或最终计费账号/额度池做自动认证；
  旧 true/false 组合不会被静默迁移。

## 四、设置页

- 单列卡片：名称行（启用开关 + 名称 + 类型小标签 + 上/下移），长说明与「连接与凭据」默认折叠。
- 内置与自定义渠道仍在**同一个全局顺序**里混排（不是分组、不把自定义挪到末尾）。
- 两类阈值分开表达：余额类旧字段是「侧栏显示告警额度」（只影响胶囊状态灯），
  模型「额度策略」是另一组按渠道/窗口的两档阈值。
- 底部保存/放弃吸底，显示「有未保存更改」；保存先校验、一次提交、只写变更字段。

## 五、稳定性与边界

- 配置身份：Host 用「公开配置摘要 + 逐渠道身份」决定是否作废旧观察；客户端在渲染时再校验一次，
  避免旧响应回填。
- 凭据：不读取、不复制、不解析第三方插件自有登录文件；WorkBuddy 走网关 Bearer；
  自定义条目的凭据由 DSH 的**模型配置**托管，插件按所选来源解析使用、不另存、不回显。
- 保存事务：没有 `mutate` 能力又需要写 secret 时整页拒绝，绝不先写元数据再提示取消。
- 未验证边界（不主张）：同 step 重试提示、月窗口、真实 Android 机型、模型侧最终计费账号/额度池
  均未做端到端实测；界面与提示只依据已观察到的请求路由与本插件自己的采样。
- 发布说明中的行为均为本地验收结果；线上版本以 GitHub / npm 为准。
