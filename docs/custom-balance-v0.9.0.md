## 1. 用户已确定的目标

1. 0.9.0 去除 Kimi Code、GLM 智谱、GLM Z.AI 三个内置渠道的显示，用户已不再使用。
2. 在插件设置页**最下方**新增“自定义余额渠道”，允许添加多个厂商：厂商名称、余额 API 完整 URL、API Key、结果 JSON 键路径。
3. Key 可复用 DSH 模型配置中的凭据，行为遵循现有“插件显式填写优先，留空则解析凭据引用”，不要求重复粘贴。
4. 自定义渠道必须具备失败回退、胶囊行和详情卡片，不能只新增一个 API 请求。
5. 仅做普通“API Key → HTTP JSON → 剩余余额”能力，不为其他特殊渠道写专用适配。

下文区分“用户确定目标”与“推荐实现细节”；额外字段、数值限制及计算模式是待冻结的技术方案，不当成用户已拍板。

## 2. 内置渠道退场与兼容

精确 id：`kimi-code`、`glm-zhipu`、`glm-zai`（ZAI 即现有 GLM Z.AI，不是额外删除 OpenCode）。其余内置渠道保留。

建议将“去除显示”落实为**从活动内置清单退场**：胶囊、详情卡片、设置页开关、渠道排序候选和模型工具均不再出现；Host 也不为隐藏条目继续轮询。这样不留下“前端不显示、后台仍发请求”的无用取数。

迁移边界：

- 升级时忽略旧启用配置和旧 `planOrder` 中的三个 id，不自动删除模型凭据、profile 配置或用户历史记录。
- 对老配置采用只读容错/兼容 schema 的方式，避免未知字段导致整插件加载失败。是否保留废弃 schema 字段由实际配置框架验证后决定，不提供可见复活开关。
- [Host 注册表](../plans/index.js)和[客户端元数据](../client.js)必须同步；只删客户端数组不够，其未知 id 回退仍可能画出一行。
- 持久化排序在有效活动 id 上重新计算，旧 id 不占上移/下移槽位；新自定义 id 不得与内置/已退场 id 冲突。
- 保留旧 parser 及 fixture 作历史维护资料即可，不要求删除物理文件，也不修 Kimi 的口径、ratio-pool 或 Cookie 月限。
- 显式模型工具请求退场 id 建议返回受控 `unknown` + `retired-channel`，不查上游、不参与收尾。它与已知活动渠道 disabled、未知 id 参数错误不同。

## 3. 设置页与配置模型

### 3.1 布局与交互

内置渠道配置之后、整页“保存/放弃”按钮之前，固定一个独立“自定义余额渠道”区域，不随内置渠道排序移到中间。每个自定义条目可添加、编辑、启用/停用、删除、上移/下移；整页统一草稿、保存、放弃与 saving/只读禁用状态。

最小字段：

| 字段 | 要求 |
| --- | --- |
| 厂商名称 | 必填，只作显示；不作为 id 或凭据解析依据，安全转义、限制长度 |
| 余额 API URL | 必填完整 HTTPS URL，不自动把模型 baseURL 当余额地址 |
| API Key | 密码输入，可留空复用模型凭据；不允许以 URL query 存 Key |
| 余额 JSON 键路径 | 必填，例如 `data.balance` 或 `balance_infos[0].total_balance` |

推荐辅助项：币种（CNY/USD/其他明确单位）、凭据来源/引用、可选余额扣减键。币种不能由厂商名称或 `$` 猜测；未指定时显示裸数并注明未指定币种，不默认所有厂商都是人民币。低余额告警阈值可选且默认关闭，尤其不能擅自继承 DeepSeek 的 10 元阈值。

### 3.2 稳定身份与秘密存储

- 为每条记录创建不可由名称推导的稳定 id，例如 `custom:<uuid>`；同名不同 URL 仍独立，改名不丢排序身份。
- 元数据包含 id/name/enabled/url/balancePath/currency/credentialRef 及可选 subtractPath；Key 必须以 DSH 支持的 secret 字段保存，不能夹在普通 JSON 字符串中假装加密。
- 优先验证 `Config` 是否支持数组对象的嵌套 `.role('secret')` 及表单保存/脱敏。若不支持，公开元数据与独立 secret 映射分开托管；同样先做凭据保存/不回显/保留旧值契约测试。
- 不能把掩码当新 Key 保存；显式清除、未修改、填入新值必须区分。删除条目可以清理本插件拥有的该条秘密，但不删除共享模型凭据。
- 保存后 Host 通过现有 liveConfig 读取；无 configEditor 的移植端明确提示“保存后重启生效”，不声称所有环境热更新。
- 建议对数量、名称、URL、路径和响应体设上限，编码前冻结限制；重复 id、坏数组等一条配置错误不能拖垮所有内置渠道。

## 4. 模型凭据复用

已核实 [resolveApiKey](../plans/util.js#L322-L348)是“插件 Key → 按引用名调用 credentials.resolve”，不是“按显示名称自动搜遍模型账户”。内置 DeepSeek 有固定 `DEEPSEEK_API_KEY`，自定义厂商没有天然固定候选名。

推荐：API Key 输入下方提供“使用模型凭据”的来源选择/引用字段，只列安全的标识与厂商名，不把 Key 返回浏览器。若宿主无可靠枚举接口，则允许填写明确凭据引用，并给出可操作说明；不得凭名称猜一组别家引用逐个试用。

优先级：显式插件 Key → 用户选定的模型凭据引用 → `no-key`，不回退到任意其他厂商 Key。凭据服务缺失/throw/null 要隔离处理。引用指向不可复用的 OAuth 或非字符串登录态时，说明不支持，不自行获取 token。

用户配置 URL 是 Key 的发送目标：保存时展示目标主机，并说明选定凭据只发送到该地址；改 URL 主机必须重新确认凭据绑定，且旧余额/旧在途请求失效。不能因为 Key 恰好存在就在未确认的新域名自动试发。

## 5. 通用 HTTP 与 JSON 能力边界

### 5.1 请求

首版建议只支持 `GET` + `Authorization: Bearer <Key>` + `Accept: application/json`。这是覆盖 DeepSeek/OpenRouter 类余额接口的通用交集；任意 POST body、自定义鉴权头、Cookie、OAuth、网页抓取、签名、多阶段请求和订阅窗口均不纳入。

请求只能在 Host 发起，不从浏览器直连余额 API，不让 Key 进入返回用量的接口、日志、异常原文、命令行或诊断截图。底层可共享传输能力，但不直接把现有 [curlJson](../plans/util.js)的通用业务信封规则当任何厂商的规范：自定义响应必须按原始 JSON + HTTP 状态 + 用户选定键解析，不能一见 `code` 就套内置厂商的成功码。

超时需包含排队、读取 body、后端降级全过程，不允许 30s×三后端串联突破 Client40s。建议自定义整批最多约 30s，单条更短并设置受控并发/数量，超时或未调度完的条目转结构化暂时失败；成功内置数据仍返回。具体上限先冻结并用虚拟时钟测试，不以增加客户端超时掩盖无界等待。

### 5.2 JSON 路径与数值

支持安全、有限的对象字段 + 数组下标路径，例 `data.balance`、`balance_infos[0].total_balance`。若需支持字段名自带点，可选择 JSON Pointer，先固定一种明确定义的语法；不执行 JavaScript/模板/eval，也不实现完整 JSONPath、通配、过滤器或脚本。

只读取对象自身属性，禁止 `__proto__`/`prototype`/`constructor` 路径，限制深度与索引。缺键/null/布尔/对象/数组/NaN/Infinity/空字符串/带货币符号的字符串均不能变成 0；有限数值与严格十进制字符串可接受。真实 0 有效，负余额可显示为欠费，不用钳成 0。金额显示沿用不向上多显示一分的规则，并补负数精度测试。

### 5.3 DeepSeek / OpenRouter 示例的关键差别

- DeepSeek 可从 `balance_infos[0].total_balance` 取余额；数组中币种顺序并非通用保证，使用者应核对自己的响应与币种。本功能不新增币种选择器或复制内置 DeepSeek 账号优先、赠金明细、峰谷条等适配。
- **“只配置一个 JSON 键”不一定能表示 OpenRouter 的账户剩余余额。**常见 credits 响应为累计 `data.total_credits` 和累计 `data.total_usage`，剩余须相减；Key 的 `limit_remaining` 也不应冒充账户余额。
- 推荐通用的最小扩展：默认“直接取余额键”，可选“余额键值 − 扣减键值”，例如 `data.total_credits` 减 `data.total_usage`。仅这一个固定运算，不开放任意表达式，也不按厂商名称自动套公式。
- 这项扩展及 OpenRouter 所需 Key 权限属于编码前确认/补证项。若不采纳扣减键，必须明确仅支持直接返回剩余值的接口，不能同时声称已支持该 credits 格式。
- 官方资料入口：[DeepSeek 查询余额](https://api-docs.deepseek.com/api/get-user-balance/)、[OpenRouter credits](https://openrouter.ai/docs/api/api-reference/credits/get-credits)。本轮抓取 OpenRouter 正文受网络安全检查阻止，未核验最新响应/Key 权限，实施模型须用可访问的官方文档或脱敏样本补证，不绕过限制、不凭示例宣称真机兼容。

## 6. URL 安全与响应边界

推荐仅允许公网 HTTPS，无 URL userinfo/fragment/Key query；拒绝 localhost/回环、私网、链路本地、云元数据地址及非 HTTP 协议，覆盖 IPv4/IPv6、DNS 重绑定和重定向。默认不跟随重定向，至少不允许把 Authorization 转发到新 origin。所有支持后端必须遵守同一规则，不能 fetch 拦住后 Python/curl 绕过。

仅做字符串 host 检查不能防重绑定；实施前验证宿主安全出网能力。若暂不能保证 DNS/连接目标一致，就限制使用固定、核验后的公网目标或暂停发送已保存模型凭据，不宣称 SSRF 已解决。不新增本地服务适配。

TLS 错误不能用关闭证书校验解决；返回体、URL 和错误脱敏，限制 body 大小和解析深度。厂商名称与响应文案都视为不可信文本。

## 7. 失败回退：完整复用体验，不掩盖配置错误

| 场景 | Host/客户端行为 |
| --- | --- |
| 网络、DNS/TLS、超时、429、5xx | 暂时失败；已有该条成功值时保留旧余额、状态点及数值变灰；连续第 8 次失败才改纯错误行 |
| 第一次请求即失败 | 无旧值可保留，直接给失败与可操作提示，不伪造 0 |
| 缺 Key、明确 401/403、非法 URL/JSON 路径配置 | 需用户操作的语义/配置错误，立即提示，不用旧值顶着 |
| 2xx 非 JSON/缺键/类型不符 | 不猜为余额 0；建议作为暂时的响应结构错误，旧值最多沿用至阈值；卡片显示“响应中未找到有效余额”等固定诊断 |
| HTTP400/404/405 等端点错误 | 固定配置错误提示，不根据自由文案猜登录失效；不能把自定义 404 说成“插件未安装” |
| 停用/删除/更改 URL、引用、Key、路径、币种或计算模式 | 该条旧值、失败计数、缓存及在途身份全部失效；不沿用旧账户/旧币种余额 |
| 恢复成功 | 新值替换旧值，清连续失败计数，取消灰色；单条失败不影响其他条目 |

JSON 键拼错与上游结构变动不能仅从一次响应区分：保存时校验语法，运行时缺键采用有上限的暂时降级，并明确诊断。建议增加手动“验证配置”入口时，应单独确认其出网行为；不默默对每次输入触发请求。

失败计数按稳定 id + 配置代次隔离；一个渠道故障只影响自己。所有错误条目不携带旧 balance 等数据字段，避免错误态仍画出余额。维持点击展开/focus/visibilitychange 强刷与旧响应作废逻辑。

## 8. 胶囊与详情卡片

- 每个已启用自定义条目独占一行：状态点 + 用户厂商名称 + 币种/余额，数值右对齐、沿用现有截断规则；名称长时省略并用 tooltip 给完整名称，不能挤坏数值。
- 成功正常色；暂时失败的旧值与状态点同为灰色；错误态显示失败/配置提示，旧余额不残留；零余额不是失败。
- 每条独立详情分区：厂商名称、余额、币种、正常/降级/错误状态及固定可读原因；不展示 API Key、完整敏感 URL、原始 JSON 或错误堆栈。
- 不臆造现金/赠金、积分、额度条、峰谷条或重置时间；不为自定义渠道借用 DeepSeek 的账号与充值逻辑。
- 自定义显示排序建议为内置之后的独立块，内部按自定义列表顺序；设置编辑区始终在底部。若后续要求跨内置排序需另确认，不能默默改变已定位置。
- rail 态继续不可交互、只显示状态点；详情遵守现有外点/Esc 关闭、WAAPI 降级、独占 footer 行和无正 z-index 约束。

必须覆盖：

1. 旧配置把三渠道全启用仍无显示/无请求、旧排序无空槽，模型凭据未删除；其余内置渠道正常。
2. 添加两条同名厂商、重命名/排序不串数据；停用/删除不请求；保存/放弃/保存中/只读/坏配置/服务缺失均正确。
3. 显式 Key 优先、模型引用复用、缺凭据/错误引用可操作；秘密掩码不覆盖旧 Key，wire/日志无秘密。
4. 直接值/嵌套/数组路径、数值字符串、0、负数、缺值、非法类型、越界、可选扣减；OpenRouter 示例不把总充值或 Key 限额当账户剩余。
5. 单条和两条分别模拟网络/429/5xx/语义/结构错误；前 7 次灰化、第 8 次纯错误、恢复；名称和余额仍按每条正确显示。
6. 更改账号/URL/路径/币种后的迟到旧响应不回填，删除后不复活，错误态无旧数据字段；其他内置与自定义行不被单条失败拖垮。
7. 超时/队列/并发及响应体上限、全链路不超 Client40s；恶意路径、URL、重定向、DNS/IPv6/本地地址和日志泄露测试。
8. 长名称、不同币种、深浅主题、rail、详情开关、外点/Esc、安卓无 shell/可选服务降级与现有 footer/层级守卫。

本轮未实现或实测新能力；历史 0.8.5 回归不能证明上述用例已通过。编码完成后仍需用户试装；不改当前本地版本、不推送、不发布。

### 10.1 与设计一致的冻结项

| 设计条目 | 落地 |
| --- | --- |
| 退场 id `kimi-code` / `glm-zhipu` / `glm-zai`，双端注册表 + 设置 + 排序 + 后台取数 | ✅ `plans/index.js` 的 `PLANS` 与 client.js 的 `PLANS` 同步移除；`RETIRED_PLAN_IDS` 保留历史 id |
| 稳定不可推导 id | ✅ `custom:<randomUUID 前 16 位>`；客户端 `newClientCustomId()` 有 `crypto` 缺失时的回退 |
| 仅 `GET` + `Bearer` + JSON | ✅ `plans/custom-balance.js` 的 `requestJson` |
| 键路径只支持字段 + 下标，不执行表达式 | ✅ `parseJsonPath`，拒绝 `__proto__`/`prototype`/`constructor` |
| 0 有效、负数保留、缺值/非法类型不当 0 | ✅ `numberFromJson` / `extractCustomBalance` |
| 可选固定扣减键（唯一运算） | ✅ `subtractPath`；缺扣减键返回 `subtract-missing`，不把累计值当余额 |
| 暂时失败灰化保旧值、第 8 次转纯错误 | ✅ 复用 `FAIL_THRESHOLD = 8` |
| 语义/配置错误立即提示 | ✅ `auth` / `no-key` / `credential-unconfirmed` / `config` / `endpoint` 均无 `transient` |
| 配置身份变化作废旧值与在途响应 | ✅ `gen`（身份字段 + Key 指纹） |
| 设置区固定在内置渠道之后、保存按钮之前 | ✅ C2b/C2c |
| 不跟随重定向、拒绝私网/环回/云元数据 | ✅ `redirect:'error'` + `validateBalanceUrl` + `verifyPublicTarget` |
| 响应体大小、超时、并发、数量上限 | ✅ 256 KiB / 10 s（整批 20 s）/ 3 / 12 |

### 10.2 与设计不同之处（都是实施时的判断，已记录理由）

1. **Key 存放位置：用 `z.dict(z.string().role('secret'))`，不是数组元素里的 secret 字段。**
   设计第 3.2 节提出「优先验证数组对象嵌套 `.role('secret')`」。核实宿主源码后确认嵌套 secret
   *确实*被 `redactSecrets` 正确处理，但**数组方案有实际缺陷**：客户端拿到的是「已剥掉 secret
   的数组」，若它回写整个数组（`form.set('customBalances', …)`），就会把「它从未收到过」的
   Key 全部抹掉。改用独立 dict 后可以按 `['customKeys', id]` 路径 set/unset，只动目标条目。
   代价：需要新增 `/api/plan-usage/custom-status` 路由来告诉设置页「哪些 id 已有 Key」
   （只回布尔）。测试 H5d 明确守住「条目数组内不含 secret 字段」。

2. **新增了一条只读路由 `/api/plan-usage/custom-status`。**
   设计里没有它。原因是 `ConfigFormController` 的快照**只含 `value`**，不含 `secrets` 侧信道，
   所以设置页无法从表单本身得知「这条是否已保存 Key」，也就无法渲染「已配置/未配置」与「清除」。
   该路由只回 `{keys:{id:bool}, refs:{id:bool}}`，已用秘密哨兵验证不泄露（H4a–d）。

3. **自定义条目固定排在内置渠道之后，不参与 `planOrder`。**
   设计第 8 节写的是「建议为内置之后的独立块」。实施时把这条定为规则：自定义条目由 Host 按
   配置顺序返回，客户端不再排序它们；设置页的自定义编辑区也固定在最下方。若将来要跨内置排序，
   需要另开需求。

4. **`credentialHost` / `urlHostConfirmed` 双字段。**
   设计要求「改 URL 主机必须重新确认凭据绑定」。实施时用两个字段表达：`credentialHost` 记录
   **已确认**的主机，`urlHostConfirmed` 记录确认时的 URL 主机（用于审计）。客户端改 URL 时把两者
   一起清空，用户必须显式点「确认把该凭据发送到此主机」才恢复；Host 侧则拒绝 `credentialHost`
   与当前 URL 主机不一致的请求（`credential-unconfirmed`），**零请求**（F6c）。

5. **币种不提供下拉，只接受 2–6 位字母代码或留空。**
   设计提到「推荐辅助项：币种（CNY/USD/其它明确单位）」。实施时不做固定枚举，因为无法预知
   所有上游币种；留空表示「未指定」，界面明确写「未指定币种」并显示裸数字，**绝不默认人民币**。

6. **没有低余额告警阈值。**
   设计第 3.1 节说「低余额告警阈值可选且默认关闭」。本版**未实现**（避免不必要地扩大范围），
   文档与测试都明确记录这一缺口。

### 10.3 实施中发现的真实问题（已修，均有守卫用例）

| 问题 | 现象 | 修法 | 守卫 |
| --- | --- | --- | --- |
| 排序残留退场 id | 点「上移」看起来没动（槽位被 `glm-zai` 等占住） | `orderedIds()` 只保留活动渠道；`movePlan` 落盘时不再写回退场 id | C1g–i |
| 鉴权错误被笼统化 | 401 在胶囊里只显示「获取失败」，用户不知道该改 Key | 胶囊按 `error` 分类显示「鉴权失败 / 配置有误 / 请设置 Key / 凭据待确认」 | R6、R7c |
| 重定向被误分类 | `redirect:'error'` 抛 `TypeError('fetch failed')`，原因藏在 `err.cause`，被报成「网络不可达」 | 遍历 `cause` 链匹配 `redirect`，归为 `endpoint` 语义错误 | S2a |
| 超时依赖传输层 | 不理会 `AbortSignal` 的 transport 会让整批无限挂起 | `requestJson` 在请求层 race 一个定时器，到点即 settle | F10、S8 |
| volatile 包装未解包 | 无 `configEditor` 的部署里 `cfg.enabled === false` 恒不成立，开关实际失效（0.8.x 遗留） | `cfgValue()` 统一解包 `{get()}` 与原始 JSON | H5e、H1d |
