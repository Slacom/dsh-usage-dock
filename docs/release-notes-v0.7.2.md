# dsh-usage-dock v0.7.2 — 修回详情面板的额度条 + 缩略态圆点居中

> 上一版：**v0.7.1**。本版修两个 **0.7.1 引入/遗留**的显示问题，取数逻辑与配置项未动。
> ⚠️ v0.7.1 的详情面板**不显示额度进度条**，建议直接升到 0.7.2。

---

## 1. 详情面板里 OpenAI Codex 没有额度条了（0.7.1 引入的回归）

**现象**：展开详情面板后，`5小时 / 周限` 这几行只剩「标签 + 百分比 + 剩余时间」竖着堆在一起，
**中间那条进度条整个不见了**（真机截图：`0%1 小时` / `68%7 天` 挤成一列）。

**根因**：一个 JavaScript **变量遮蔽**。

`client.js` 模块级本来就有一个给面板额度行用的样式：

```js
var rowStyle = { display: 'flex', alignItems: 'center', gap: 8, margin: '6px 0' }
```

0.7.1 为了让胶囊向外贴边 4px，在**组件内部**又写了一个同名变量：

```js
var rowStyle = null          // ← 0.7.1 引入的 bug
if (ownRow) { rowStyle = wide ? { …贴边样式… } : { … } }
```

`var` 声明会被提升到**整个函数作用域**，于是组件里渲染面板额度行时用的 `rowStyle`
不再是模块级那个 flex 样式，而是这个局部变量 —— 面板还没被打开时它是 `null`，
被打开后它又变成根节点的贴边样式。两种情况都让额度行**丢掉 `display: flex`**，
label / 进度条 / 百分比 / 剩余时间于是从"一行四列"退化成"竖排文字"，
进度条因为宽度塌成 0 而看不见。

**修法**：把局部变量改名（`ownRowStyle`），并在代码注释里写明"这个作用域里不要再有
叫 `rowStyle` 的变量"，同时把面板渲染处的依赖关系记下来。

> 这个教训是通用的：`var` 没有块级作用域，**同名的局部变量会静默接管外层模块级变量**。
> 该不该用同名，编译器不会提醒，只有测试与真机能发现。

## 2. 缩略（rail）态状态点没有居中，而是贴左

**现象**：侧栏折叠成 rail 后，两个状态圆点贴在左侧，而不是像其他图标那样居中。

**根因**：胶囊是 **column 方向**的 flex 容器。0.6.3 起为了"折叠时不出面板"，
给胶囊写的居中是 `justifyContent: 'center'` —— 但 column 容器里 `justifyContent` 管的是
**纵轴**，对横向居中完全无效；而子项在 `align-items: stretch`（默认值）下会被拉成满宽，
圆点自然就落在左端。

**修法**：缩略态补 `alignItems: 'center'` —— 子项不再被拉伸，而是按内容宽度**水平居中**。
**展开态保持 `undefined`（默认 stretch）**，因此圆点、名称、数值的横向位置一行未动
（测试 T11 专门断言"展开态不得出现 alignItems"）。

## 验证

浏览器半回归测试扩到 **11 项**，两条新用例都**先在 v0.7.1 上跑失败、在修复版上跑通过**，
证明它们真的守得住这两个 bug：

```
用 v0.7.1 的 client.js 跑：
[FAIL] T10 面板额度行 — 面板里应有 5小时/周限 两条额度行，实际 0
[FAIL] T11 缩略态圆点居中 — 缩略态圆点必须水平居中
11 项：9 通过, 2 失败

用修复后的 client.js 跑：
[PASS] T10 面板额度行：flex 布局 + 进度条完整（守住 var 遮蔽回归）
[PASS] T11 缩略态圆点居中，展开态位置不受影响
11 项：11 通过, 0 失败
```

- **T10** 打开详情面板，遍历组件树找出两条额度行，断言它们是 `display:flex` 的四列结构、
  且进度条轨道（height 6）与百分比填充（`width: NN%`）都在；
- **T11** 断言缩略态 `alignItems === 'center'`、展开态**没有**该属性。

取数套件（8 项）与缩略交互套件（4 项）复跑无回归。

